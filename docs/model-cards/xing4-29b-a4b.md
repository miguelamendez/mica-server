# Xing4.0-29B-A4B — compression experiment

- [Original BF16 weights](https://huggingface.co/XingChen-AGI/Xing4.0-29B-A4B), Apache-2.0, pinned source revision `baae3c3e813cad5f888f1f485cfff659c89076c5`. The 41 published safetensors shards total 62,431,083,040 bytes (58.14 GiB). This is not an inference-ready BF16 checkpoint on the local 24 GiB Mac.
- [Publisher GGUF](https://huggingface.co/XingChen-AGI/Xing4.0-29B-A4B-GGUF), pinned revision `b8cd0a75f3d3dfa992bd8423ee22041b987eaf44`. Its sole file, `xing4_0-29b-IQ4_NL.gguf`, is 20,104,012,544 bytes (18.72 GiB) with SHA-256 `9c9c81cf83b6ce974d3440088318de83b727c0064124ca6c3c919289adadb4dd`. `IQ4_NL` is a mixed-precision 4-bit-class quant, not Q4_K_M.
- Architecture: the [published config](https://huggingface.co/XingChen-AGI/Xing4.0-29B-A4B/blob/main/config.json) and [model implementation](https://huggingface.co/XingChen-AGI/Xing4.0-29B-A4B/blob/main/modeling_xing4_0.py) define 40 decoder layers (two dense, then 38 MoE), hidden size 3,584, expert width 1,024, MLA attention, 64 routed experts per MoE layer, top-4 routing, one shared expert, and four-stream mHC hyperconnections. The safetensors index also contains an appended layer 40 for MTP. The model declares 262,144 context tokens. The experimental profile deliberately permits only 2,560 total tokens and one request.
- Engine: upstream llama.cpp support is [pending](https://github.com/ggml-org/llama.cpp/pull/29012). The candidate Mica engine pins the author's [Xing-capable fork](https://github.com/shuxiaoqiong/llama.cpp/tree/xing4_0-port) at `63c16fb9797d00f13d70b5a618b4deb08953aef3`. A successful compile is not yet proof of correct Metal inference.
- Memory: the `mica-xing-q4-baseline-macos` profile uses a **20 GiB admission budget** and a provisional 19 GiB model reservation. Mica's current admission setting is not an OS-enforced physical-memory ceiling. Launch only with an external memory guard, with all other model workers stopped. The uncompressed GGUF file is already too large for a 16 GiB profile before KV cache and runtime buffers.

## Folding study

### Structural validation before downloading weights (22 September 2026)

This is a source/configuration audit, **not** a compressed-model quality result. The [Xing-specific GGUF converter](https://github.com/shuxiaoqiong/llama.cpp/blob/xing4_0-port/conversion/xing.py) inherits config-driven expert count/width from the DeepSeek converter, recognizes the appended MTP layer, and supports `--no-mtp`. The [C++ loader](https://github.com/shuxiaoqiong/llama.cpp/blob/xing4_0-port/src/models/xing4_0.cpp) allocates expert and layer tensors from GGUF metadata. Thus a coherently rewritten BF16 checkpoint can, in principle, be converted and loaded without a fixed 64-expert or 40-layer shape baked into this fork. An export/load test is still required.

| Intervention | Shape-level feasibility | Main constraint |
| --- | --- | --- |
| Routed-expert pruning, 64→48 or 64→40 | Yes: remove selected experts, compact their IDs, and rewrite each layer's router weights and correction biases; keep top-4 and the shared expert. | Router choice and rare specialists may be damaged. Frequency-only pruning is an insufficient quality proof. |
| Routed-expert merging | Yes: combine corresponding experts and aggregate their router probability mass, then export a smaller pool. | SwiGLU is nonlinear; averaging experts or router rows is not function-preserving. Requires alignment and measured output reconstruction. |
| Neuron/channel folding inside experts, width 1,024→768 or 640 | Yes: transform gate/up rows and down columns together, then update `moe_intermediate_size`. | The width is global in the current config, so shared experts and the MTP expert layer must also match or the exporter/loader must be extended for per-layer widths. |
| Decoder-layer pruning or span merging, 40→32 | Metadata and code permit a changed layer count with contiguous reindexing and MTP moved to the new final index. | mHC performs input-dependent four-stream mixing around attention and FFN; deleting or averaging layer weights is not function-preserving. Needs calibrated span replacement and longer-context checks. |
| Drop MTP only | Converter has `--no-mtp`; the ordinary decoder can remain unchanged. | Loses MTP speculative decoding and saves only the appended predictor, not enough alone to meet 16 GiB. Verify ordinary logits match. |

The 38 main-decoder routed expert banks contain approximately `38 × 64 × 3 × 3584 × 1024 = 26.78B` BF16 parameters, or about 85.8% of the indexed checkpoint bytes; this excludes the appended MTP expert bank. Assuming the publisher's mixed-precision allocation scales proportionally, 64→48 would project the 18.72 GiB GGUF to about **14.7 GiB**, while 64→40 would project it to about **12.7 GiB**. These are accounting estimates, not produced files, quality measurements, or peak-RAM claims. The 48-expert variant leaves very little headroom inside a 16 GiB runtime budget; 40 experts is a more credible first fit target.

The baseline and the proposed compressed checkpoint are separate experiments:

1. Verify publisher IQ4_NL load, output, decode speed, and measured peak RSS with the pinned fork. Save per-token reference logits on a frozen calibration/evaluation set.
2. Fold **BF16 routed experts first**, retaining token embeddings, MLA, mHC, shared experts, normalization, and top-4 routing while explicitly remapping the router. Start with 64→48 experts per MoE layer as a quality pilot; test 64→40 as the more plausible 16 GiB fit. Compare against expert-width folding at the same byte budget. An optional calibration pass may be needed; full gradient distillation is outside the initial research constraint. Expert count is an experiment variable, not an achieved compression result.
3. Convert each folded BF16 checkpoint to GGUF and quantize with a recorded IQ4_NL recipe. Record tensor-type distribution and calibration corpus. Never repeatedly quantize the publisher's Q4 file as the main quality comparison.
4. On identical token prefixes and template settings, report mean and distribution of `KL(P_reference || P_candidate)` over the full vocabulary, plus task accuracy, perplexity, prefill/decode speed, actual peak memory, and file size. The local Q4 may serve as a *surrogate* reference; a true BF16 reference needs a larger machine or a verified out-of-core logits path. Quantization-only and folding-only deltas must be separated when that reference is available.
5. Only after expert-level results, consider layer reduction (40→32) with calibration. MLA layers are structurally similar, but mHC connects layer states; removing whole layers is higher-risk and cannot be inferred safe from file-size arithmetic.

Passing the 16 GiB profile requires measured runtime memory below the limit, not merely a GGUF below 16 GiB. A practical file-size target is approximately 13–14 GiB to leave room for KV cache and runtime buffers; this is a planning target, not a guarantee.
